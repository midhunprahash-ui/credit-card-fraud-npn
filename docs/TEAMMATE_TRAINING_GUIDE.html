Lightning AI Teammate Training Guide

Follow the steps from top to bottom. One person from each pair performs the official run and sends the complete result ZIP to Midhun.

Steps 1. Find your notebook 2. Create a Studio 3. Clone the project 4. Create Kaggle token 5. Add Lightning secret 6. Prepare the data 7. Quick test 8. Final training 9. Find results 10. Create ZIP Final checklist

All notebooks are inside notebooks/lightning_ai/.

2Create a Lightning AI Studio

  1. Sign in to Lightning AI.
  2. Create a new persistent Studio.
  3. Name it after your model, such as fraud-lightgbm or fraud-catboost.
  4. Keep the Studio until the final ZIP has been downloaded.

3Clone the project

Open the Lightning terminal and run:

git clone https://github.com/midhunprahash-ui/credit-card-fraud-npn.git
cd credit-card-fraud-npn
git switch main
git pull origin main
pip install -r requirements-training.txt
Important: Use main for official training. Do not train from develop.

4Create a Kaggle API token

  1. Sign in to Kaggle.
  2. Open the IEEE-CIS Fraud Detection competition.
  3. Join the competition and accept its rules.
  4. Open your Kaggle account Settings.
  5. Find API Tokens and select Generate New Token.
  6. Copy the new token immediately and keep it private.
Security: Never send the token in chat, include it in a screenshot, paste it into a notebook cell, or commit it to GitHub.

5Add the token to Lightning AI Secrets

  1. Select your profile picture in the top-right corner of Lightning AI.
  2. Open Global settings.
  3. Select Secrets.
  4. Select New Secret.
  5. Use the following exact secret name:
KAGGLE_API_TOKEN
  1. Paste your Kaggle token into the secret value field.
  2. Save the secret.
  3. Close and reopen the Studio terminal.
  4. Restart the Jupyter notebook kernel.

Do not print the token to test it. Notebook 00 checks it safely.

6Prepare the data

Open this notebook:

notebooks/lightning_ai/00_shared_data_preparation.ipynb

Choose Kernel → Restart Kernel and Run All Cells.

It downloads the data, performs the left join, creates shared features and chronological splits, and saves them under:

data/processed/
Do not continue until notebook 00 finishes without an error. Use a CPU machine with 24–32 GB system RAM when available.

7Perform a quick test

Open your assigned notebook. Find:

FAST_RUN = False

Temporarily change it to:

FAST_RUN = True

Restart the kernel and run every cell.

This only checks that the code works. Never use fast-run metrics in the final comparison or presentation.

8Run the official training

Change the setting back to:

FAST_RUN = False

Restart the kernel and run every cell again. Do not independently change the split, preprocessing, features, metrics, or random seed.

Required: The final reload test must pass. This proves that the saved model can be loaded and used again.

9Find the complete result folder

The notebook creates one self-contained folder:

artifacts/<model-name>/<run-id>/

It contains the trained model, preprocessing, input schema, threshold, metrics, predictions, configuration, interpretation output, and checksum manifest.

Share the whole folder. The model file alone is not enough for deployment.

10Create and share the ZIP

The notebook prints the exact result folder. Replace the placeholders below with those printed values:

zip -r model_results.zip artifacts/<model-name>/<run-id>/

Example for CatBoost:

zip -r catboost_results.zip artifacts/catboost/20260814_143000/

Download the ZIP from Lightning AI and send it to Midhun.

Final checklist

  • Notebook 00 completed successfully.
  • The correct assigned model notebook was used.
  • The official run used FAST_RUN = False.
  • The final reload test passed.
  • The complete run folder was zipped.
  • No Kaggle or cloud secret is inside the ZIP.
  • The final ZIP was sent to Midhun.
